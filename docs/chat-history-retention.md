## 規則

- 前台仍套用原有 48 小時期限與發訊息授權，沒有開放過期聊天室。
- `planDataRetention` 僅決定移出即時資料的項目。伺服器把 requests、responses、invitations、chatMessages 移至獨立 Redis hashes：`<環境前綴>:sl:chat-history:v1:<集合>`，不設定 TTL。
- Redis Lua 先保存目前值再移除即時值，單筆移動不可被另一個請求插入；封存寫入失敗不會先刪除該筆即時值。重試不會拿舊快照覆蓋已封存值。
- 一般同步不讀取保存区；A000 聊天室查詢合併即時與封存紀錄、按 id 去重。摘要不含聊天文字或照片 URL。詳細內容取消原本默默只取最後 500 則的限制。
- 清空前台資料、刪除客戶帳號會保留共同聊天證據。參與者 ID、訊息原欄位、局及回應原欄位保留；帳號遭刪除後，名稱可能回退成 ID，不保證完整帳號快照。
- A000 在聊天室詳情輸入 `DELETE <threadId>` 可刪除指定 threadId + requestId 的封存訊息與邀請。尚有即時資料則拒絕；A777/其他使用者不得使用此 API。
- 記錄刪除請求及完成事件；刪除前稽核寫入失敗則不刪。若完成稽核寫入失敗，API 報錯但資料可能已刪，需檢查紀錄後再重試。
- 手動刪除對話不刪共用局／回應摘要，也不刪儲存服務上的照片檔案，UI 明確提示。歷史照片引用納入 Blob 盤點及小姐／幹部照片刪除檢查。幹部一般圖片刪除遇到聊天引用會保留檔案。

## 驗證與限制

- 新增 5 項記憶體儲存整合測試：到期仍保存、501 則完整讀取、權限與確認、精確刪除與稽核、帳號與清空操作保護、歷史照片檔案保護。
- 保留期限／歷史局 7 項既有測試及聊天授權／同步／上傳／幹部生命週期／後台／配對 98 項既有測試通過，共 110 項不同測試。
- src 原始碼 TypeScript 檢查通過。原專案 `tsc --noEmit` 被既有 `.next/dev/types/validator.ts:156` 產生檔語法錯誤擋住；`next typegen` 成功但未修復該 dev 產生檔。
- 尚未在 Redis 測試環境驗證 Lua、完整 build 或瀏覽器端操作；未部署、未對正式資料執行搬移／刪除。
- 不會恢復過去已刪除的訊息。無 Redis 的本機記憶體 fallback 不具重啟持久性。
- 不自動清理不等於備份。Redis 備份與容量告警仍需獨立設定；外部 R2 生命週期、人工刪檔及供應商故障不在本次程式保護範圍。
- 一般客戶同步不載入歷史，但 A000 後台目前仍讀取完整保存集合；歷史量大時需要再做索引、分頁／冷儲存，不能宣稱無限量零成本。
