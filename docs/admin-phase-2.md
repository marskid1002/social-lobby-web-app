# A000 管理後台第二階段

> 2026-07-30 本機實作狀態：事件追蹤、A000 時間軸、問題回報、幹部帳號生命週期、裝置摘要與 session 失效均已完成第一版；尚未 commit、push 或部署，需通過最終驗收後再決定是否上線。

## 目標

第二階段把第一版依現有資料推算的流程診斷，升級成可追查單次事件的營運工具；同時補齊 A000 的幹部帳號生命週期管理。

## 事件追蹤

- 每次關鍵操作由伺服器產生 `traceId`。
- 可用帳號、遮罩手機、局、聊天室、時間與 `traceId` 搜尋。
- 記錄客戶發局、幹部派工、客戶同意、伺服器建立聊天室。
- 記錄推播服務接受、通知連結開啟、進入聊天室。
- 記錄訊息寫入與訊息推播結果。
- 顯示完整時間軸並自動標記卡住的流程。
- 記錄保存約 30 天；清除測試局時不清除診斷紀錄。
- 不記錄 OTP、密碼、啟用碼明文、secret 或完整聊天內容。
- 手機號碼一律遮罩。

## 問題回報

客戶端與幹部端可新增「回報問題」入口，自動附上：

- 自己的帳號識別
- 發生時間與當前頁面
- 局編號與聊天室編號
- 最近安全錯誤碼
- 裝置與瀏覽器
- `traceId`

## 幹部帳號生命週期

- A000 可新增幹部帳號，不再依賴程式碼固定增加 `Axxx`。
- 帳號代碼由伺服器配置並保證唯一。
- 每位幹部使用獨立、一次性的啟用碼。
- 啟用碼只保存雜湊；明文只在產生當次顯示一次。
- 啟用成功後立即失效。
- A000 可重新產生啟用碼；舊碼立即撤銷。
- A000 可編輯幹部顯示名稱與必要基本資料。
- A000 可停用、重新啟用或封存幹部。
- 有歷史派工、聊天室或稽核紀錄的幹部不得硬刪；封存後保留歷史關聯。
- 無任何歷史關聯的未啟用測試帳號，才可在二次確認後永久刪除。
- 所有新增、重發啟用碼、停用、啟用、封存與刪除操作都寫入 A000 稽核。
- 不在稽核或 API response 中記錄啟用碼、密碼或 secret。

## 權限與失效政策

- 所有帳號操作必須同時通過 A000 session 與伺服器帳號角色驗證。
- 前端不可自行指定角色、`userId`、tier 或帳號代碼。
- 停用、封存、重設密碼或重設裝置時，增加 session/token version，使既有 JWT 失效。
- Push subscription 以帳號與裝置管理。
- A000 可查看裝置摘要並執行「登出所有裝置」。

## 2026-07-30 雙端流程基準

本機雙端實測已通過：

1. 客戶發出「喝一杯／信義區／1 人」。
2. 幹部建立並派出一位小姐。
3. 客戶看到一筆加入回應並接受。
4. 伺服器建立帶正確 `requestId` 的聊天室。
5. 客戶與幹部進入同一聊天室。
6. 客戶訊息經伺服器接受後顯示於幹部端。
7. 幹部回覆後，客戶重新同步可看到回覆。

基準測試同時確認：目前聊天室仍顯示約 30 天期限；改為 48 小時屬後續既定產品項目，不在第二階段事件追蹤內偷偷變更。
